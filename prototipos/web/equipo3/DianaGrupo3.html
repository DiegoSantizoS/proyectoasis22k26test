5. Integración contable, saldos y controles

Caso de estudio: Embutidos de Calidad, S.A.

5.1 Objetivo

Analizar cómo los ERP integran las compras y pagos con los módulos financieros y contables, y qué controles implementan para garantizar la integridad de las operaciones.

5.2 Integración con Contabilidad

El sistema solicitado debe generar automáticamente el enlace con Contabilidad para las pólizas derivadas de compras y pagos. La integración esperada sería:

Rama: Compra

  1. Compra
  2. Cuenta por pagar
  3. Póliza contable

Rama: Pago

  1. Pago
  2. Disminución de cuenta por pagar
  3. Movimiento bancario
  4. Póliza contable

5.4 Controles de integridad

Se compararán los mecanismos utilizados por cada ERP para impedir:

  • Pagos duplicados
  • Facturas duplicadas
  • Pagos superiores al saldo
  • Compras sin autorización
  • Cambios posteriores a una aprobación
  • Eliminación de operaciones contabilizadas
  • Acceso de usuarios no autorizados

5.5 Roles

Cada operación pasa por un responsable distinto, lo que separa funciones y refuerza la trazabilidad del proceso:

Rol Acción
Analista de comprasCrear orden
Jefe de comprasRevisar orden
GerenciaAutorizar
BodegaRegistrar recepción
Cuentas por pagarRegistrar factura
TesoreríaEjecutar pago
ContabilidadValidar póliza

5.6 Auditoría

Cada operación debería conservar:

  • Usuario
  • Fecha
  • Hora
  • Acción realizada
  • Datos anteriores
  • Datos nuevos
  • Estado de la transacción

El benchmarking permitirá identificar cómo los ERP analizados administran el ciclo completo de proveedor, compra, recepción, cuenta por pagar, pago y contabilización. La integración contable no es un paso aislado, sino una consecuencia automática y controlada de cada compra y cada pago: toda operación queda enlazada a una póliza, todo saldo queda respaldado por un movimiento verificable, y toda acción queda atribuida a un usuario y un momento.
